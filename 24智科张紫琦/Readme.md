# RM 自瞄系统（传统灯条检测 + PnP）

对 RoboMaster 考核数据包做离线处理：按 `video/frames.csv` 的时间顺序读帧，用颜色阈值找灯条、两两配对成装甲板，用 135×56 mm 小装甲板模型做 PnP 解算，输出带标注的 mp4，并在控制台打印统计。

## 1. 目录结构

```
CMakeLists.txt
src/
├─ common/types.hpp            LightBar / Armor(P1-P4) / ArmorPose / ArmorObservation
├─ io/dataset.hpp              frames.csv + video.avi 顺序读帧（时间基准只用 csv）
├─ io/calib.hpp                calibration/ 下三个 yaml 的解析与一致性校验
├─ detect/detector.hpp         检测器接口
├─ detect/color_detector.hpp   颜色检测参数
├─ detect/color_detector.cpp   颜色分割、灯条筛选、配对、P1-P4 构造
├─ geometry/pnp.hpp            PnP 接口
├─ geometry/pnp.cpp            IPPE 双解选优 + LM 精化 + 回投校验 + 三维中心
├─ viz/overlay.hpp             绘制接口
├─ viz/overlay.cpp             灯条框、P1-P4 四边形、中心点、z 标注、HUD
└─ app/main.cpp                命令行、串联流程、统计、写视频
data/
├─ 2026-11-13_18-25-25_462305/ 考核视频1：目标自转
└─ 2026-11-13_18-28-12_830451/ 考核视频2：目标左右平移
out/                           输出视频
```

## 2. 环境要求

- Ubuntu 22.04（实测），CMake ≥ 3.16，g++ 支持 C++17
- OpenCV ≥ 4.5（实测 4.5.4），需带 FFMPEG videoio 与 H.264 编码器
- 无需 ROS，无第三方依赖

## 3. 构建

在工程根目录执行：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

生成可执行文件：`build/rm_autoaim`。

## 4. 运行两段考核视频

> 程序只接收“数据目录”，会自己找该目录下的 `video/video.avi`、`video/frames.csv` 和 `calibration/`，不要单独传视频路径。

视频1（目标自转，1770 帧）：

```bash
./build/rm_autoaim data/2026-11-13_18-25-25_462305 \
  --out out/2026-11-13_18-25-25_462305_overlay.mp4
```

视频2（目标左右平移，1240 帧）：

```bash
./build/rm_autoaim data/2026-11-13_18-28-12_830451 \
  --out out/2026-11-13_18-28-12_830451_overlay.mp4
```

只处理前 300 帧快速自检：

```bash
./build/rm_autoaim data/2026-11-13_18-25-25_462305 --max-frames 300 --out out/check.mp4
```

蓝色目标示例（默认是红色）：

```bash
./build/rm_autoaim data/<数据包名> --enemy blue --threshold 50 --out out/blue.mp4
```

不传 `--out` 时自动输出到 `out/<数据目录名>_overlay.mp4`。

## 5. 参数说明（以源码为准）

### 5.1 命令行参数

| 参数                    | 必填 | 默认值                               | 含义                                       |
| --------------------- | -- | --------------------------------- | ---------------------------------------- |
| `<数据目录>`（位置参数）        | 是  | 无                                 | 数据包根目录，内含 `video/` 与 `calibration/`      |
| `--out <path.mp4>`    | 否  | `out/<数据目录名>_overlay.mp4`         | 输出视频路径，父目录会自动创建                          |
| `--fps <f>`           | 否  | `0`（用 frames.csv 推算的标称帧率，约 165.9） | 输出视频帧率，仅影响播放速度，不影响算法时间基准                 |
| `--max-frames <n>`    | 否  | `-1`（全部帧）                         | 只处理前 n 帧                                 |
| `--enemy <red\|blue>` | 否  | `red`                             | 目标颜色，只支持 `red` / `blue`                  |
| `--threshold <n>`     | 否  | `50`                              | 颜色通道差值二值化阈值（`R-max(G,B)` 或 `B-max(G,R)`） |
| `--show`              | 否  | 关闭                                | 同步窗口显示，需要图形环境                            |

### 5.2 需求项与程序接口对应

| 需求项  | 程序中的实际形式                                                                                                                                      |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 输入视频 | 不单独传文件；传 `<数据目录>`，程序读取 `<数据目录>/video/video.avi`，帧顺序与时间戳来自 `<数据目录>/video/frames.csv`                                                           |
| 相机参数 | 无需命令行参数；自动读取 `<数据目录>/calibration/intrinsics.yaml`、`handeye.yaml`、`calibration.yaml`，使用其中 `camera_matrix` 与 `distort_coeffs` 做 PnP，并校验三个文件是否一致 |
| 目标颜色 | `--enemy red` / `--enemy blue`，默认 `red`                                                                                                       |
| 输出路径 | `--out <path.mp4>`；默认 `out/<数据目录名>_overlay.mp4`                                                                                               |

### 5.3 代码内的检测/解算参数（`src/detect/color_detector.hpp`）

目前这些是 `ColorDetector::Params` 的默认值，未开放为命令行参数：

| 参数                    | 默认值      | 含义                               |
| --------------------- | -------- | -------------------------------- |
| `color`               | `kRed`   | 目标颜色（由 `--enemy` 覆盖）             |
| `threshold`           | `50`     | 颜色通道差值阈值（由 `--threshold` 覆盖）     |
| `close_size`          | `5`      | 闭运算核大小，用于连接灯条光晕的断口               |
| `min_bar_aspect`      | `1.5`    | 灯条高/宽比下限                         |
| `max_bar_aspect`      | `20.0`   | 灯条高/宽比上限                         |
| `min_bar_height`      | `26` px  | 灯条最小长度（1440×1080 下的有效射程保护）       |
| `min_bar_area`        | `25` px² | 轮廓最小面积                           |
| `armor_width_mm`      | `135`    | 小装甲板宽度                           |
| `armor_height_mm`     | `56`     | 小装甲板高度（等于灯条长度）                   |
| `max_width_ratio`     | `1.22`   | 配对宽度比相对 135/56 的上限倍数（超出视为不是同一块板） |
| `min_width_ratio`     | `0.60`   | 配对宽度比下限（大角度偏转时投影变窄）              |
| `max_height_ratio`    | `1.6`    | 两灯条高度比上限（允许一条灯条断亮变短）             |
| `max_center_dy_ratio` | `0.4`    | 两灯条中心竖直偏差 / 较矮灯条高度               |
| `max_overlap_ratio`   | `0.35`   | 允许两灯条水平重叠 / 较宽灯条宽度               |

PnP 固定参数（`src/geometry/pnp.cpp`）：物点 `(±0.0675, ±0.028, 0)` m，`SOLVEPNP_IPPE` 两解 + LM 精化，四角平均回投误差上限 `8 px`。

## 6. 处理流程

1. **读帧**：按 `video/frames.csv` 行顺序解码 `video.avi`；所有时间仅用 csv 的 `elapsed_s`，不使用 AVI 容器 fps。
2. **颜色分割**：红目标用 `R − max(G,B)`，蓝目标用 `B − max(G,R)`；按 `threshold` 二值化；再做 `5×5` 闭运算连接断口。灯条中心会过曝成白色，颜色掩码只剩外圈光晕（呈空心环），因此**不做开运算、也不做“轮廓面积/外接矩形面积”过滤**，否则会把细灯条腐蚀掉。
3. **灯条筛选**：外接矩形宽 ≥3 px、高 ≥26 px 且不超过图像半高、不贴图像顶部；高/宽比在 `[1.5, 20]`；轮廓面积 ≥25 px²。
4. **配对**：
   - 两灯条高度比 ≤ 1.6；
   - 两灯条中心竖直偏差 ≤ `0.4 × 较矮灯条高度`；
   - 并集外接矩形宽度 ÷ **较高灯条高度** 落在 `[2.41×0.60, 2.41×1.22]`（2.41 = 135/56）；超出宽度就不是同一块小装甲板；
   - 两灯条水平重叠不超过较宽灯条的 35%；
   - 按 `|宽度比−2.41|/2.41 + 0.5×高度差 + 0.5×竖直偏差` 打分，贪心选取，每个灯条只用一次；一个灯条同时匹配多块板时保留分数最高（最近/最正）的一对。
5. **P1–P4 四边形**：取左灯条左上外角、右灯条右上外角、右灯条右下外角、左灯条左下外角，约定从左上角开始顺时针为 P1、P2、P3、P4。
6. **断亮补救**：若一条灯条明显短（高度比 < 0.85）且只有一端与较长的灯条对齐（差值 ≤ `max(2 px, 6% × 较长高度)`），说明是下段不亮而不是透视收缩，用较长灯条把该端补齐；这样四角仍保持矩形一致。
7. **PnP**：以 135×56 mm 构造物点，与 P1–P4 一一对应；`solvePnPGeneric(SOLVEPNP_IPPE)` 得到平面二解，选“板面 x 轴在图像平面内倾角（roll）最小”的解，再用 `solvePnPRefineLM` 精化；把四物点回投并与 P1–P4 比较，平均像素误差 > 8 px 则丢弃该板。
8. **三维中心**：`tvec` 即装甲板中心在相机坐标系下的位置（米）；中心点取 `(0,0,0)` 的投影，不使用四角像素平均。`yaw = atan2(nx, -nz)`、`pitch = asin(ny)`，法线统一翻向相机一侧。`Armor::center` 另存对角线 P1–P3 与 P2–P4 的交点，作为 2D 校验/兜底。
9. **绘制与输出**：
   - 黄色：两条灯条外接框；
   - 绿色：P1–P4 四边形及四角标签；
   - 红色圆点：三维中心投影；
   - 黄色 `z=…m`：该板距离；
   - 左上 HUD：帧号、时间戳、armors/bars、检测与 PnP 耗时、最近目标的 x/y/z、yaw/pitch、回投误差。
   - 输出 H.264(`avc1`) mp4。本数据约 166 fps，`mp4v` 的 timebase 上限 65535 放不下，因此不用 mp4v。

## 7. 控制台输出

程序会打印：

- `frames`：csv 行数与视频容器帧数
- `time`：首帧、末帧 `elapsed_s` 及跨度
- `nominal`：由 csv 推算的帧率
- `calib K/D`、`handeye`
- `detector`、`pnp` 配置
- `armors`：检出帧比例、装甲板总数
- `detect` / `pnp`：单帧平均与最大耗时
- `pose z`：有效解算的 z 范围与均值

## 8. 后续需优化问题

1. **灯条下段不够亮**：已通过“配对时用较高灯条高度作参考、高度比放宽到 1.6、必要时补齐较短灯条端点”缓解；如仍偶发配不上，可优先调 `--threshold`（例如 45–60）与 `close_size`。
2. **旋转到特定倾角时，右侧灯条矩形框偏大**：这是灯条光晕与相邻结构/另一灯条粘连导致的连通域变大。当前回投误差上限 8 px 能兜底（这类帧误差约 4–6 px，仍会被保留），但框会略大。后续可调整 `--threshold`、缩短 `close_size`，或增加“灯条最大宽度/最大面积”约束、按竖直投影拆分过宽连通域。
3. **单帧四点 PnP 的 pitch 二解歧义**：近正面时两解回投误差接近，目前用 roll 最小选解；接入 EKF 跟踪后可用帧间连续性消歧。
4. **尚未实现（相对完整方案）**：`bench.csv` 逐帧耗时记录、灯条 L/R 文字标注、0.1 m 相机坐标三轴、PCA/最小二乘中心轴拟合、灯条倾角 ±30° 与填充率过滤。当前版本以“稳定打框 + 三维中心”为目标，上述项可在后续阶段补充。
