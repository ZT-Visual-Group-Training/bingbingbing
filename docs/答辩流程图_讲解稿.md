## 一、系统流程图逐环节讲词（照着念即可）

按图上 ①→⑪ 的顺序讲，每一步一句话：

**① 视频逐帧读取**
"统一入口是 main.cpp，video 模式逐帧读取官方视频，1440×1080，一共 1770 帧。"

**② ROI 裁剪 + 模糊 + HSV**
"先做预处理：跳过画面上方 35%，只扫下面有装甲板的区域，这是零损失的提速；再高斯模糊去噪，把 BGR 转 HSV，红蓝共用一次转换。"

**③ 红蓝颜色掩膜**
"第二步颜色分割：用 inRange 按 HSV 阈值把红色和蓝色灯条抠出来，两张掩膜按位或，再用 3×3 开运算去噪、闭运算填小孔。"

**④ 轮廓查找 + 椭圆拟合**
"在掩膜上找轮廓，每个亮区拟合一个椭圆，统一成'宽小于高'的竖直灯条。"

**⑤ 六项关卡筛选灯条**
"这是关键：不是所有亮区都是灯条。用六个条件过滤——面积、点数、倾角、宽高比、充实地度、高度，全过才算真灯条。这一步把余光和噪点挡在外面（细节见第二张图）。"

**⑥ 断截合并**
"官方视频里灯条会被暗缝断成两截，我们用轮廓合并把同一列、间隙小于 14 像素的上下两截接回来再拟合。"

**⑦ 左右灯条配对 → 四角点**
"把两根同色灯条配成一对，按几何关系规整出四个角点，中心点取四角平均。"

**⑧ 时序多数投票修歪框〔可选〕**
"如果一根灯条长期断着，合并也接不回来，框会被压歪。我们用前几帧的历史判断它是不是真断，是就用长的那根修框高。这是个可选模块，用 --temporal 开启，默认关闭。"

**⑨ PnP 解算三维坐标**
"拿到四角点后，用 solvePnP 配合官方相机内参和小装甲板真实尺寸 135×56 毫米，算出装甲板中心的三维坐标和直线距离，单位是米。"

**⑩ IMU 姿态 + 手眼坐标转换〔可选〕**
"再接入 IMU：读四元数解出 roll/pitch/yaw 姿态角，用官方手眼外参把 PnP 的相机系坐标换算到云台坐标系。默认自动开，--no-imu 可关。"

**⑪ 结果绘制与写盘**
"最后把框、四角点、中心点、灯条识别点、三维坐标、耗时都画到画面上，叠加 IMU 姿态角，写成结果视频。"

**收尾一句话**：
"整套系统的核心思路就是——先用颜色找到灯条，用形状筛掉干扰，再用几何配成板，最后用 PnP 和 IMU 把二维画面变成三维信息。"

## 二、灯条筛选四步图 · 怎么讲

这张图是 `debug_pipeline` 程序用**真实视频第 150 帧**生成的，从左到右四列：

| 列 | 画面 | 讲解要点 |
|---|---|---|
| Step1 | 原始裁剪图 | 画面上有灯条、数字"3"、还有一片余光 |
| Step2 | 颜色掩膜 | 红色框标出颜色阈值抓到的亮区——注意余光 #3 也被圈进来了，说明**光靠颜色不够** |
| Step3 | 形状筛选 | 余光 #3 被淘汰（涂黑），只剩两根真灯条 #0 和 #2 |
| Step4 | 最终灯条 | 两根灯条被绿色椭圆框准确框住 |

下方四张**判定卡**是重点，讲的时候指着卡片说：

- **#0 PASS / #2 PASS**：aspect 0.34 / 0.21（≤0.5）、angle 6.75° / 1.93°（≤40°）、height 43 / 80（≥20）——六项全过，是真灯条。
- **#1 REJECT**：aspect 0.56 超了 0.5，height 只有 14 < 20——它是碎片。
- **#3 REJECT**：aspect 0.77 超了、angle **-48.45°** 远超 40°（横躺的），判定卡上标了红框 "GLOW (horizontal reflection)"——这就是**余光**。

**一句话总结**：颜色负责"找得到"，形状负责"选得对"，两者结合才能稳。

## 三、老师可能问的问题（提前准备）

**Q1：为什么用 HSV 不用 RGB？**
A：RGB 三通道耦合，光照变化会把颜色值整体抬高；HSV 把亮度 V 单独分离，调阈值时不受明暗影响，灯光忽明忽暗也能稳定识别。

**Q2：六个筛选条件为什么是这些值？**
A：都是拿官方视频实测调出来的。灯条是竖直细长条，所以宽高比≤0.5、倾角≤40°；面积和高度挡噪点；充实地度挡中空的反光。答辩时可以说"阈值来自实测统计，不是拍脑袋"。

**Q3：灯条断成两截怎么办？**
A：先做轮廓级合并——同一列、间隙≤14px、倾角接近的上下两截接回来；接不回来的长期断裂，用时序多数投票取较长那根修框高（可选模块）。

**Q4：PnP 为什么能测距？**
A：四角点在图像上的像素位置已知，装甲板的真实物理尺寸已知（135×56mm），相机内参已知，三点齐全就能用 `solvePnP` 反解出装甲板相对相机的三维位置。

**Q5：IMU 有什么用？为什么不直接用 PnP 结果？**
A：PnP 给的是**相机坐标系**下的位置，但相机装在云台上会转动。IMU 提供云台姿态，配合手眼外参把坐标换算到稳定的 body 系，这样结果不随云台晃动而乱跳。

**Q6：做了哪些速度优化？**
A：红蓝共用一次颜色转换、ROI 只扫下方 65%、掩膜阶段合并处理；检测耗时从 67.7ms 降到约 35ms，没有降分辨率所以远距离小板一个没丢。

## 四、现场演示建议

答辩现场按这个顺序演示，最稳：

1. **主程序**：CLion 选 `armor_vision` target 运行，播放结果视频，展示检测框、四角点、距离、耗时、IMU 姿态角。
2. **算法细节**：选 `debug_pipeline` target 运行（默认参数即可），现场生成第二张图，指着判定卡讲余光筛选。
3. **IMU 体检**：选 `imu_check` target 运行，秒出姿态角和手眼转换结果，证明 IMU 模块真的工作。

> 三张图/程序都在这份交付副本里，拷走即可用；`--temporal` 是可选加分项，老师问到"断灯条"时再提。
