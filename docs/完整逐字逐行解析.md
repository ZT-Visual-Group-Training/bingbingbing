# 第一部分 A：运行输出逐字解析

## A1. 构建日志（build 时终端打印的）

构建时我们敲了一条命令让 CMake 重新配置再编译，终端输出（已过滤掉无关的 OpenCV 插件警告）：

```
-- Configuring done (3.1s)
-- Generating done (0.6s)
-- Build files have been written to: D:/demo5/cmake-build-debug
CMAKE_BUILD_TYPE:STRING=Release
ninja: no work to do.
```

逐行拆：

| 原文 | 逐字解释 |
|---|---|
| `Configuring` | 配置阶段。CMake 读取 `CMakeLists.txt`，检查编译器、OpenCV 在不在、参数对不对。 |
| `(3.1s)` | 这个阶段花了 3.1 秒。 |
| `Generating` | 生成阶段。CMake 根据配置产出真正的构建脚本（这里是 Ninja 用的文件）。 |
| `(0.6s)` | 生成花了 0.6 秒。 |
| `Build files ... D:/demo5/cmake-build-debug` | 生成的构建文件放在这个目录。`cmake-build-debug` 是 CLion 默认构建目录名，**名字叫 debug 但实际编译的是 Release**（见下一行）。 |
| `CMAKE_BUILD_TYPE:STRING=Release` | 关键！构建类型=发布版。我们明明传了 Debug，但 `CMakeLists.txt` 里写了"强制改成 Release"，所以这里显示 Release。为什么？因为本机 OpenCV 只有 Release 版动态库，Debug 版缺 `libopencv_calib3d4d.dll`，用 Debug 编译的程序一运行就会缺库崩溃。强制 Release 保证你能直接点运行。 |
| `ninja: no work to do.` | Ninja（构建工具）说"没什么要做的"。意思是源码没有改动，exe 已经是最新的，不用重新编译。这不是错误，恰恰说明上次编译的产物还在、是完好的。 |

> 补充：还有一条被过滤掉的警告 `CMakeLists.txt:15 (find_package)` + `This warning is for project developers`。这是 OpenCV 4.14 自己的一句提示，说它的某个 CMake 配置写法比较老。**不影响功能**，Ubuntu 上的 OpenCV 4.5.4 不会有这句。

| `输入视频: test_scene.avi \| 640x360 \| 30fps \| 共 90 帧` | 程序打开刚生成的视频，读到四个信息：文件名、分辨率 640 宽×360 高、帧率 30、总帧数 90。`\|` 是我的排版分隔，原文是空格。 |

| `处理完成，共 90 帧` | 视频读到结尾，`while` 循环结束，打印总数。 |

| `结果视频已保存: armor_result.avi` | 处理后的视频（每帧画了框和字）写到了这个文件。 |

|---|---|---|

# 第二部分 B：源代码逐行解析

## B0. 文件之间的关系（先看这个再读代码）

5 个文件不是各写各的，它们分工协作：

```
CMakeLists.txt    → 告诉编译器"要编译哪些文件、怎么链接"
ArmorDetector.h   → 说明书：定义了 CameraCalib/ArmorParam/LightBar/Armor 四种数据 + ArmorDetector 类
ArmorDetector.cpp → 说明书的实现：检测算法全在这里（核心）
main.cpp          → 图片版入口：读一张图 → 调 detect() → 存结果
main_video.cpp    → 视频版入口：循环读每帧 → 调 detect() → 写成视频
```

`main.cpp` 和 `main_video.cpp` 都 `#include "ArmorDetector.h"` 并调用同一个 `detect()`——**算法只有一份，两个入口共用**。这就是为什么视频版不用重写检测逻辑。

## B1. CMakeLists.txt 逐行（31 行）

这是"给编译器的说明书"，告诉 CMake 怎么把源码变成 exe。

```cmake
cmake_minimum_required(VERSION 3.10)      -- 第1行
project(demo5)                             -- 第2行
set(CMAKE_CXX_STANDARD 17)                 -- 第4行
if(NOT CMAKE_BUILD_TYPE)                   -- 第9行
    set(CMAKE_BUILD_TYPE Release CACHE STRING "Build type" FORCE)
elseif(CMAKE_BUILD_TYPE STREQUAL "Debug")  -- 第11行
    set(CMAKE_BUILD_TYPE Release CACHE STRING "Build type" FORCE)
endif()
find_package(OpenCV REQUIRED)              -- 第15行
add_library(armor_core ArmorDetector.cpp)  -- 第18行
target_include_directories(armor_core PRIVATE ${OpenCV_INCLUDE_DIRS})
target_link_libraries(armor_core PRIVATE ${OpenCV_LIBS})
add_executable(armor_video main_video.cpp) -- 第23行
target_include_directories(armor_video PRIVATE ${OpenCV_INCLUDE_DIRS})
target_link_libraries(armor_video PRIVATE armor_core ${OpenCV_LIBS})
add_executable(demo5 main.cpp)             -- 第28行
target_include_directories(demo5 PRIVATE ${OpenCV_INCLUDE_DIRS})
target_link_libraries(demo5 PRIVATE armor_core ${OpenCV_LIBS})
```

逐行/逐块讲：

- **第 1 行 `cmake_minimum_required(VERSION 3.10)`**：声明"这份配置至少需要 CMake 3.10 版"。低于这个版本会报错。Ubuntu 22.04 自带的 CMake 是 3.22，满足。
- **第 2 行 `project(demo5)`**：给项目起名叫 demo5。
- **第 4 行 `set(CMAKE_CXX_STANDARD 17)`**：用 C++17 标准编译。为什么 17？代码里用了 `enum class`、`auto`、`std::filesystem` 等较新特性中的一部分（这里主要是 `enum class` 和结构化习惯）。11 其实也够，17 更保险。
- **第 6~8 行**（注释）：解释为什么要强制 Release。
- **第 9~13 行 `if/elseif/endif`**：强制把构建类型设为 Release。
  - `if(NOT CMAKE_BUILD_TYPE)`：如果没指定构建类型 → 设为 Release。
  - `elseif(CMAKE_BUILD_TYPE STREQUAL "Debug")`：如果指定的是 Debug → 也改成 Release。
  - `set(... CACHE STRING "Build type" FORCE)`：`FORCE` 表示强制覆盖。`CACHE` 表示写进缓存。
  - 这就是 A1 里"传了 Debug 却显示 Release"的原因。
- **第 15 行 `find_package(OpenCV REQUIRED)`**：让 CMake 去找 OpenCV 库。`REQUIRED` = 找不到就报错停止。找到后它会提供两个变量：`OpenCV_INCLUDE_DIRS`（头文件路径）和 `OpenCV_LIBS`（库文件路径）。
- **第 18 行 `add_library(armor_core ArmorDetector.cpp)`**：把 `ArmorDetector.cpp` 编译成一个**库**叫 `armor_core`（core=核心）。库不是 exe，不能直接运行，是给别的程序链接用的。因为两个入口都要用检测算法，抽成库就不用编译两遍。
- **第 19 行 `target_include_directories(armor_core PRIVATE ${OpenCV_INCLUDE_DIRS})`**：告诉编译器编译这个库时，去哪找 OpenCV 的头文件。`PRIVATE` = 只对这个目标有效。
- **第 20 行 `target_link_libraries(armor_core PRIVATE ${OpenCV_LIBS})`**：把这个库链接到 OpenCV 库上——因为它内部调用了 `cv::` 的函数，链接后才能找到这些函数的实现。
- **第 23 行 `add_executable(armor_video main_video.cpp)`**：用 `main_video.cpp` 生成一个可执行文件（exe）叫 `armor_video`。这是视频版，考核真正要用的。
- **第 24 行**：编译时给 armor_video 找 OpenCV 头文件。
- **第 25 行 `target_link_libraries(armor_video PRIVATE armor_core ${OpenCV_LIBS})`**：armor_video 要链接两样：`armor_core`（我们自己的检测库）+ OpenCV。这样它既能调用检测算法，又能调用 OpenCV。
- **第 28~30 行**：同上，生成图片版 exe 叫 `demo5`，链接同样的东西。

一句话：**`armor_core` 是共用的算法库，`armor_video` 和 `demo5` 是两个套了不同入口（视频/图片）的壳。**

## B2. ArmorDetector.h 逐行（135 行）

这是"说明书/头文件"，只放**声明**（有什么东西），不放实现（怎么做）。实现在 .cpp。

### 开头注释（1~11 行）

- `1~11` 行全是 `//` 注释，讲这个文件定义了 4 样东西：① CameraCalib 相机参数 ② ArmorParam 调参阈值 ③ LightBar/Armor 数据结构 ④ ArmorDetector 类。第 10 行那句"`.h` 负责有哪些东西，具体怎么做在 .cpp"是理解头文件的钥匙。

### 防重复包含（12~13 行 + 135 行）

```cpp
#ifndef ARMOR_DETECTOR_H     -- 第12行
#define ARMOR_DETECTOR_H     -- 第13行
...                          -- 中间全部内容
#endif // ARMOR_DETECTOR_H   -- 第135行
```

- `#ifndef ARMOR_DETECTOR_H`：**if not defined**，如果没定义过 `ARMOR_DETECTOR_H` 这个标记，就往下执行。
- `#define ARMOR_DETECTOR_H`：定义这个标记。
- `#endif`：判断结束。
- 作用：防止头文件被重复 include 时内容重复定义导致编译错误。第一次进来标记没定义→内容被读进去；第二次标记已定义→整段跳过。`ARMOR_DETECTOR_H` 只是个名字（文件名大写+_H），换成别的也行，只要三处一致。
- 你之前问过 `MYHEADER_H` 是什么——这个 `ARMOR_DETECTOR_H` 就是同一个东西，只是按这个文件名起的名。

### include（15~16 行）

- **第 15 行 `#include <opencv2/opencv.hpp>`**：引入 OpenCV 总头文件。里面 `cv::Mat`（图像）、`cv::RotatedRect`（旋转矩形）、`cv::solvePnP`（测距函数）等全在这。尖括号 `<>` = 系统/第三方库。
- **第 16 行 `#include <vector>`**：引入向量容器（用 `std::vector` 存列表）。

### 颜色枚举（18~19 行）

```cpp
enum class ArmorColor { Red = 0, Blue = 1 };
```

- `enum class`：枚举类型，一组有名字的常量。`ArmorColor::Red` 的值是 0，`ArmorColor::Blue` 是 1。
- 为什么不用裸写 0/1？可读性——`color == ArmorColor::Red` 一眼看懂，写成 `color == 0` 就得猜。这也呼应了你之前学过的"给东西起名字"。
- `class`（而不是 `enum`）让它更安全，不会和别的枚举的 Red 撞名。

### ① CameraCalib 相机标定参数（21~37 行）

```cpp
struct CameraCalib {                                    -- 第29行
    double fx = 600.0, fy = 600.0;                      -- 第30行
    double cx = 320.0, cy = 180.0;                      -- 第31行
    double k1 = 0, k2 = 0, p1 = 0, p2 = 0, k3 = 0;      -- 第33行
    cv::Mat cameraMatrix() const;                       -- 第35行
    cv::Mat distCoeffs() const;                         -- 第36行
};                                                      -- 第37行
```

- `struct`：结构体，把一组相关数据打包成一个类型。
- **21~27 行注释**：解释"标定参数"——相机把三维拍成二维会压缩+扭曲，这组数字描述怎么压怎么扭，PnP 靠它反算回三维。**默认值是占位示例，只匹配合成图**。
- **第 30 行 `fx, fy`**：焦距（单位：像素）。`f`=focal length。越大视野越窄、拍得越"远"。合成图用 600；真实相机是 2334（就在数据包里）。
- **第 31 行 `cx, cy`**：主点，光心落在画面的哪个像素。一般接近画面中心。合成图 640×360 的中心是 (320,180)，所以默认这么写。真实相机 1440×1080 是 (722.6, 534.6)。`c`=center。
- **第 33 行 `k1,k2,p1,p2,k3`**：畸变系数。镜头不是完美针孔，边缘会弯曲（桶形/枕形畸变），这 5 个数描述弯曲程度。默认 0 = 先不考虑。真实值也在数据包里。
- **第 35 行 `cameraMatrix() const`**：成员函数声明，把 fx/fy/cx/cy 拼成 3×3 内参矩阵（PnP 要的格式）。末尾 `const` = 这个函数不改对象自己。实现在 .cpp。

### ② ArmorParam 检测参数（39~71 行）

**颜色阈值（43~50 行）：**

- **46 行 `redLowH2=170, redHighH2=180`**：红色第二段 170~180。为什么要两段？因为红色在 HSV 色环上跨过 0/180 接缝（你之前详细学过）。

**灯条筛选阈值（52~58 行）—— 你 demo5 学过的那套：**

- **55 行 `lightAngleMax=40.f`**：灯条偏离竖直的最大角度 40 度，超过不像灯条。
- **56 行 `aspectRatioMax=0.5f`**：宽/高上限 0.5。灯条是细长条，宽远小于高。0.5 意味着宽不能超过高的一半。

### 第 1 步：makeColorMask 生成颜色掩膜（29~66 行）

```cpp
cv::Mat ArmorDetector::makeColorMask(const cv::Mat& bgr, ArmorColor color) const {
    CV_Assert(!bgr.empty());
    cv::Mat src = bgr;
    if (src.channels() == 4)      cv::cvtColor(src, src, cv::COLOR_BGRA2BGR);
    else if (src.channels() == 1) cv::cvtColor(src, src, cv::COLOR_GRAY2BGR);
    cv::Mat blurred, hsv;
    cv::GaussianBlur(src, blurred, cv::Size(3, 3), 0);
    cv::cvtColor(blurred, hsv, cv::COLOR_BGR2HSV);
    cv::Mat mask;
    if (color == ArmorColor::Red) {
        cv::Mat lower, upper;
        cv::inRange(hsv, cv::Scalar(param_.redLowH1,  param_.minS, param_.minV),
                         cv::Scalar(param_.redHighH1, 255, 255), lower);
        cv::inRange(hsv, cv::Scalar(param_.redLowH2,  param_.minS, param_.minV),
                         cv::Scalar(param_.redHighH2, 255, 255), upper);
        cv::bitwise_or(lower, upper, mask);
    } else {
        cv::inRange(hsv, cv::Scalar(param_.blueLowH,  param_.minS, param_.minV),
                         cv::Scalar(param_.blueHighH, 255, 255), mask);
    }
    cv::Mat kernel = cv::getStructuringElement(cv::MORPH_RECT, cv::Size(3, 3));
    cv::morphologyEx(mask, mask, cv::MORPH_OPEN, kernel);
    cv::morphologyEx(mask, mask, cv::MORPH_CLOSE, kernel, cv::Point(-1, -1), 2);
    return mask;
}
```

逐行：

- **第 31 行**：函数定义。参数 `const cv::Mat& bgr`=只读的原图（引用避免拷贝、const 保证不改原图），`ArmorColor color`=要找红还是蓝。返回 `cv::Mat`=黑白掩膜。
- **第 32 行 `CV_Assert(!bgr.empty())`**：你专门问过这行。断言"图不为空"，空就当场抛异常停下。`CV_Assert` 是格式固定、条件自由。`!bgr.empty()` = "图不为空"。
- **第 34 行 `cv::Mat src = bgr`**：`src` 指向原图。这里只是浅拷贝（共享数据），不是复制整张图。
- **第 35 行**：如果图有 4 通道（BGRA，带透明），转成 3 通道 BGR。`channels()` 返回通道数。
- **第 36 行**：如果是 1 通道（灰度图），也补成 3 通道 BGR。这样后面统一处理 3 通道。
- **第 39 行 `cv::Mat blurred, hsv`**：声明两个空矩阵，一个存模糊图，一个存 HSV 图。
- **第 40 行 `cv::GaussianBlur(src, blurred, cv::Size(3,3), 0)`**：3×3 高斯模糊，抹掉细小噪点，让颜色更平滑。`cv::Size(3,3)` 是模糊核大小。
- **第 41 行 `cv::cvtColor(blurred, hsv, cv::COLOR_BGR2HSV)`**：把图从 BGR 颜色空间转到 HSV。为什么转？因为按颜色判断（"找红色"）在 HSV 里只需看 H 一个通道，比 BGR 三个通道混合稳定得多（你之前详细学过 HSV）。
- **第 43 行**：声明输出的掩膜 `mask`。
- **第 44 行 `if (color == ArmorColor::Red)`**：如果要找红色。
- **46~49 行 第一段红**：`cv::inRange(hsv, 下限, 上限, lower)`——对每个像素，若 H/S/V 三项都落在 `[下限, 上限]` 内就设白(255)，否则黑(0)。下限是 `(redLowH1=0, minS=100, minV=80)`，上限是 `(redHighH1=10, 255, 255)`。结果存 `lower`。
- **50~52 行 第二段红**：同样方法抓 H 在 170~180 的红，存 `upper`。
- **第 53 行 `cv::bitwise_or(lower, upper, mask)`**：按位或。"只要任一段里是白，结果就是白"。两段合并成完整红色掩膜。
- **第 54~59 行 else 蓝色**：蓝色只有一段（H 100~130），一次 `inRange` 就够，不用或。
- **第 62 行 `getStructuringElement(cv::MORPH_RECT, cv::Size(3,3))`**：造一个 3×3 矩形"刷子"（结构元素），给形态学操作用。
- **第 63 行 `morphologyEx(... MORPH_OPEN ...)`**：**开运算**=先腐蚀后膨胀，擦掉孤立小白点（噪点）。
- **第 64 行 `morphologyEx(... MORPH_CLOSE, ..., cv::Point(-1,-1), 2)`**：**闭运算**=先膨胀后腐蚀，填上小白块里的小黑孔。最后那个 `2` 是重复次数，做两遍让区域更连贯。`cv::Point(-1,-1)` 是锚点，表示中心。
- **第 65 行 `return mask`**：返回清理好的掩膜。
- ⚠️ **和检测失败的关系**：这里的 `minV=80`（50 行）和红色 H 范围（45~46 行）就是灯条抓不到的嫌疑。橙色 H≈15~30 落在 0~10 和 170~180 之外，被当背景滤掉。

### 小工具：adjustRec 修正旋转矩形（68~79 行）

```cpp
cv::RotatedRect ArmorDetector::adjustRec(const cv::RotatedRect& rec) {
    cv::RotatedRect r = rec;
    if (r.size.width > r.size.height) {
        std::swap(r.size.width, r.size.height);
        r.angle += 90.f;
    }
    while (r.angle >= 90.f)  r.angle -= 180.f;
    while (r.angle <  -90.f) r.angle += 180.f;
    return r;
}
```

- **第 70 行**：函数定义。静态私有工具。
- **第 71 行 `cv::RotatedRect r = rec`**：复制一份矩形来改，不动原件。
- **第 72 行 `if (width > height)`**：如果宽比高大（即"横着的"）。
- **第 73 行 `std::swap(width, height)`**：交换宽高，让 height 永远代表长边（竖着的灯条）。
- **第 74 行 `r.angle += 90.f`**：宽高一交换，角度也要跟着转 90 度。
- **第 76 行 `while (angle >= 90) angle -= 180`**：把角度归一到 [-90, 90)。因为旋转 180 度矩形看起来一样，所以 120° 等价于 -60°。
- **第 77 行 `while (angle < -90) angle += 180`**：同理，从另一头归一。
- **第 78 行 `return r`**：返回修正后的矩形。
- 作用：让后面判断"角度是否接近竖直""宽高比"时有统一含义（你之前问过 `adjustRec` 干嘛的）。

### 第 2 步：detectLights 检测灯条（81~121 行）

```cpp
std::vector<LightBar> ArmorDetector::detectLights(const cv::Mat& bgr) const {
    std::vector<LightBar> lights;
    const ArmorColor colors[2] = { ArmorColor::Red, ArmorColor::Blue };
    for (ArmorColor color : colors) {
        cv::Mat mask = makeColorMask(bgr, color);
        std::vector<std::vector<cv::Point>> contours;
        cv::findContours(mask, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
        for (size_t i = 0; i < contours.size(); ++i) {
            float area = static_cast<float>(cv::contourArea(contours[i]));
            if (area < param_.lightAreaMin ||
                static_cast<int>(contours[i].size()) <= param_.minPoints) continue;
            cv::RotatedRect rec = adjustRec(cv::fitEllipse(contours[i]));
            if (std::fabs(rec.angle) > param_.lightAngleMax) continue;
            float aspect = rec.size.width / rec.size.height;
            float crown  = area / rec.size.area();
            if (aspect > param_.aspectRatioMax || crown < param_.crownMin) continue;
            rec.size.height *= param_.expandScale;
            rec.size.width  *= param_.expandScale;
            LightBar bar;
            bar.rect = rec; bar.center = rec.center;
            bar.height = rec.size.height; bar.angle = rec.angle; bar.color = color;
            lights.push_back(bar);
        }
    }
    return lights;
}
```

逐行：

- **第 82 行**：函数定义，返回灯条列表。
- **第 83 行 `std::vector<LightBar> lights`**：装检测到的灯条。
- **第 85 行 `const ArmorColor colors[2] = {Red, Blue}`**：一个含两个元素的数组，红和蓝。下面循环跑两遍——同样逻辑找两种颜色。
- **第 86 行 `for (ArmorColor color : colors)`**：范围 for，依次取 colors 里每个颜色。
- **第 87 行**：调上一节的 `makeColorMask` 生成该色掩膜。

### 小工具：sidePoints 取一侧角点（123~139 行）

```cpp
std::vector<cv::Point2f> ArmorDetector::sidePoints(const LightBar& bar, bool leftSide) {
    cv::Point2f pts[4];
    bar.rect.points(pts);
    std::vector<cv::Point2f> v(pts, pts + 4);
    std::sort(v.begin(), v.end(), [](const cv::Point2f& a, const cv::Point2f& b) {
        return a.x < b.x;
    });
    std::vector<cv::Point2f> side(v.begin() + (leftSide ? 0 : 2),
                                  v.begin() + (leftSide ? 2 : 4));
    std::sort(side.begin(), side.end(), [](const cv::Point2f& a, const cv::Point2f& b) {
        return a.y < b.y;
    });
    return side;
}
```

- **第 126 行**：函数定义。`leftSide=true` 取左边两点，`false` 取右边两点。
- **第 127~128 行 `cv::Point2f pts[4]; bar.rect.points(pts)`**：`points()` 把旋转矩形的 4 个顶点填进数组 pts。
- **第 129 行 `std::vector<cv::Point2f> v(pts, pts+4)`**：用数组首尾指针构造 vector v，装这 4 个点。
- **第 130~132 行 第一次 sort**：lambda 表达式（匿名函数）`[](a,b){ return a.x < b.x; }` 作为排序规则，按 x 从小到大排。排完 v[0],v[1] 是左边两点，v[2],v[3] 是右边两点。
- **第 133~134 行 取一侧**：`leftSide ? 0 : 2` 是三元运算符——true 取 0（左边两点 v[0],v[1]），false 取 2（右边两点 v[2],v[3]）。用迭代器区间构造 `side`。
- **第 135~137 行 第二次 sort**：按 y 从小到大排，这样 `side[0]`=上面的点，`side[1]`=下面的点。
- **第 138 行 `return side`**：返回 `{上点, 下点}`。

### 第 3 步：matchLights 配对+四角点（141~186 行）

```cpp
std::vector<Armor> ArmorDetector::matchLights(const std::vector<LightBar>& lights) const {
    std::vector<Armor> armors;
    if (lights.size() < 2) return armors;
    std::vector<LightBar> sorted = lights;
    std::sort(sorted.begin(), sorted.end(), [](const LightBar& a, const LightBar& b) {
        return a.center.x < b.center.x;
    });
    for (size_t i = 0; i + 1 < sorted.size(); ++i) {
        const LightBar& L = sorted[i];
        const LightBar& R = sorted[i + 1];
        if (L.color != R.color) continue;
        float hMin = std::min(L.height, R.height);
        float hMax = std::max(L.height, R.height);
        if ((hMax - hMin) / hMax > param_.pairHeightRatioMax) continue;
        if (std::fabs(L.center.y - R.center.y) > param_.pairYDiffMax) continue;
        if (std::fabs(L.angle - R.angle) > param_.pairAngleDiffMax) continue;
        float dist = R.center.x - L.center.x;
        if (dist < param_.pairDistMin) continue;
        if (dist / hMax > param_.pairDistMaxRatio) continue;
        std::vector<cv::Point2f> lp = sidePoints(L, true);
        std::vector<cv::Point2f> rp = sidePoints(R, false);
        Armor a;
        a.color = L.color;
        a.corners.push_back(lp[0]);
        a.corners.push_back(rp[0]);
        a.corners.push_back(rp[1]);
        a.corners.push_back(lp[1]);
        a.center = cv::Point2f(0.f, 0.f);
        for (const auto& p : a.corners) a.center += p;
        a.center *= 0.25f;
        armors.push_back(a);
    }
    return armors;
}
```

逐行：

- **第 143 行**：函数定义。
- **第 144 行**：装结果的装甲板列表。
- **第 145 行 `if (lights.size() < 2) return armors`**：少于 2 根灯条配不了对，直接返回空列表。（这是防御性检查。）
- **第 147 行 `std::vector<LightBar> sorted = lights`**：复制一份来排序，不动原件。
- **第 148~150 行 sort**：按灯条中心 x 从小到大排（左→右）。lambda 作排序规则。
- **第 152 行 `for (size_t i = 0; i+1 < sorted.size(); ++i)`**：只检查相邻两根。`i+1 < size` 保证不越界。这是你之前学过的 O(n) 技巧——排好序只比邻居，不用两两全试。

- **第 160 行 高度差**：`(hMax-hMin)/hMax > 0.6` 差太多不是一对。
- **第 161 行 y 差**：中心 y 差 > 40 像素，不在同一水平线，不是一对。
- **第 162 行 倾角差**：角度差 > 15 度，不是一对。

### 第 4 步：solveArmorPnP 测距（188~215 行）—— 最核心

```cpp
void ArmorDetector::solveArmorPnP(Armor& armor, const CameraCalib& calib) const {
    if (armor.corners.size() != 4) return;
    float w = param_.armorWidth * 0.5f;
    float h = param_.armorHeight * 0.5f;
    std::vector<cv::Point3f> objectPoints = {
        cv::Point3f(-w,  h, 0),
        cv::Point3f( w,  h, 0),
        cv::Point3f( w, -h, 0),
        cv::Point3f(-w, -h, 0)
    };
    cv::solvePnP(objectPoints, armor.corners,
                 calib.cameraMatrix(), calib.distCoeffs(),
                 armor.rvec, armor.tvec, false, cv::SOLVEPNP_ITERATIVE);
    armor.distance = cv::norm(armor.tvec);
    armor.valid = true;
}
```

- **188~190 行注释**：讲清楚"已知四角真实坐标+像素坐标+相机参数，求位置姿态"。
- **第 191 行**：函数定义。`Armor& armor` 不带 const，因为要往里写结果。
- **第 192 行 `if (corners.size() != 4) return`**：角点不是 4 个就放弃（防御性）。
- **194~195 行注释**：世界点用"板自身坐标系"，单位米，z=0（板是平的）。顺序必须和 corners 一一对应。
- **第 196 行 `w = armorWidth * 0.5f`**：半宽。板宽 0.425m，半宽 0.2125m。
- **第 197 行 `h = armorHeight * 0.5f`**：半高 0.1225m。
- **198~203 行 objectPoints 世界点**：4 个角在真实世界的坐标：
  - 0 号 `(-w, h, 0)` = 左上
  - 1 号 `(w, h, 0)` = 右上
  - 2 号 `(w, -h, 0)` = 右下
  - 3 号 `(-w, -h, 0)` = 左下
  - z 全是 0（平面）。y 向上为正，所以上面是 +h。
  - ⚠️ 这 4 个的顺序必须和 `matchLights` 里 corners 的 0/1/2/3 完全一致（左上→右上→右下→左下）。
- **第 205 行注释**：图像点就是 `armor.corners`（像素坐标），直接用。
- **第 208~210 行 `cv::solvePnP(...)`**：一行调用 OpenCV 的 PnP 求解器。参数依次是：
  - `objectPoints`：世界点（上面造的）
  - `armor.corners`：图像点（像素）
  - `calib.cameraMatrix()`：内参矩阵
  - `calib.distCoeffs()`：畸变系数
  - `armor.rvec`：输出——旋转向量（朝向）
  - `armor.tvec`：输出——平移向量（位置）
  - `false`：是否用初始猜测（这里不用）
  - `cv::SOLVEPNP_ITERATIVE`：算法类型（迭代法，最通用）
  - 你已经学过 PnP 的相似三角形原理，这就是它的严格实现。
- **第 213 行 `armor.distance = cv::norm(armor.tvec)`**：`norm` 算向量长度 = 直线距离（米）。
- **第 214 行 `armor.valid = true`**：标记解算成功。

### makeFrame 造动画的一帧（23~49 行）

```cpp
static cv::Mat makeFrame(double phase) {
    cv::Mat img(360, 640, CV_8UC3, cv::Scalar(35, 35, 35));
    int rx = 60 + static_cast<int>(50 * std::sin(phase));
    cv::rectangle(img, cv::Rect(rx, 100, 180, 160), cv::Scalar(20, 20, 20), cv::FILLED);
    cv::rectangle(img, cv::Rect(rx + 30, 130, 16, 100), cv::Scalar(0, 0, 255), cv::FILLED);
    cv::rectangle(img, cv::Rect(rx + 140, 130, 16, 100), cv::Scalar(0, 0, 255), cv::FILLED);
    double s = 1.0 + 0.35 * std::sin(phase * 0.7 + 1.0);
    int bw = static_cast<int>(180 * s), bh = static_cast<int>(160 * s);
    int bx = 380 - (bw - 180) / 2;
    int by = 100 - (bh - 160) / 2;
    int lw = static_cast<int>(16 * s), lh = static_cast<int>(100 * s);
    int ly = by + (bh - lh) / 2;
    cv::rectangle(img, cv::Rect(bx, by, bw, bh), cv::Scalar(20, 20, 20), cv::FILLED);
    cv::rectangle(img, cv::Rect(bx + 30, ly, lw, lh), cv::Scalar(255, 0, 0), cv::FILLED);
    cv::rectangle(img, cv::Rect(bx + bw - 30 - lw, ly, lw, lh), cv::Scalar(255, 0, 0), cv::FILLED);
    cv::GaussianBlur(img, img, cv::Size(5, 5), 0);
    return img;
}
```

- **第 27 行**：函数定义。`phase`=相位，每帧不同，驱动动画。
- **第 28 行**：造深灰背景（同图片版）。
- **第 31 行 `rx = 60 + 50*sin(phase)`**：红板的 x 坐标。`sin` 在 -1~+1 之间摆动，乘 50 得 -50~+50，加 60 得 10~110——红板左右晃。你之前专门学过"sin 驱动动画"。
- **32~34 行**：画红板（黑底+两条红竖条），位置用 rx，所以会跟着动。
- **第 37 行 `s = 1.0 + 0.35*sin(phase*0.7+1.0)`**：蓝板缩放系数，在 0.65~1.35 之间变化。`0.7` 让蓝板变化和红板不同步，`+1.0` 是相位偏移。
- **38~42 行**：按缩放系数 s 计算蓝板的宽 bw、高 bh、位置 bx/by、灯条宽 lw/高 lh、灯条 y 起点 ly。全部乘 s 或按 s 调整居中。
- **43~45 行**：画蓝板（黑底+两条蓝竖条），尺寸随 s 变化——模拟"由远及近"，这样 PnP 测距会逐帧变化。
- **第 47 行 `GaussianBlur`**：模糊。
- **第 48 行 return**。

# 结语：这次"生成的东西"串成一句话

**构建**：CMake 按 `CMakeLists.txt` 把一个算法库（`armor_core`）+ 两个入口（图片版、视频版）编译成 exe，强制 Release 保证在你的环境能跑。

**运行**：图片版/视频版入口调用同一个 `detect()`——它内部依次做 `makeColorMask`（HSV 抠色）→ `findContours`+`fitEllipse`（找灯条）→ `matchLights`（配对取四角点）→ `solvePnP`（测距）——最后 `drawResult` 画框、坐标、耗时。

**结果**：程序层面完全正常（1770 帧全过、退出码 0），但**真实视频检测不到装甲板**，因为灯条是橙色而参数按纯红设（`redLowH1=0/redHighH1=10` 等），加上 `minV=80` 对暗光偏严——从 `frame_dump.png` 上没有检测框可以直接看出。

**下一步**（等你发话）：抽真实灯条的 H/S/V 值 → 放宽颜色阈值到橙色区 → 用数据包里的真实相机内参替换占位值 → 重新构建运行，让装甲板真正被框出来。
