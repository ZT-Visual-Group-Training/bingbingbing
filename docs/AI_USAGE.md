# AI 辅助使用说明

按考核要求，如实说明参考来源、AI 的使用范围、本人完成的内容。

## 一、参考来源

动手前调研并阅读了以下开源实现。**没有复制任何仓库的源代码**，只借鉴流程结构与参数取值范围；所有阈值都在本机两段考核视频上重新实测。

| 项目 | 链接 | 借鉴了什么 |
|---|---|---|
| simple_aim（sp_vision_25 教学版） | https://gitcode.com/seu-cx-solaris/simple_aim | 五步流水线（灯条 → 配对 → PnP → 绘制）与"一个环节一个函数"的模块划分 |
| sp_vision_25（同济 SuperPower） | https://github.com/TongjiSuperPower/sp_vision_25 | 跟踪状态机 `lost → detecting → tracking → temp_lost → lost`；卡尔曼新息检验 |
| RP_Infantry_Plus（深大步兵） | https://github.com/yarkable/RP_Infantry_Plus | 通道相减 + 亮度掩膜 + 双掩膜融合的颜色分割思路 |
| armor_tracker（ROS2） | https://index.rosdabbler.com/p/armor_tracker/ | 卡尔曼状态量取 `[x, y, z, vx, vy, vz]` 的匀速模型 |
| 考核包 `source_demo.yaml` | 本仓库数据包 | `min_detect_count: 5`、`max_temp_lost_count: 15`、`min_lightbar_ratio: 1.5`、`max_angle_error: 45°` |

算法本身（颜色分割、最小外接矩形筛选、两两配对、solvePnP、卡尔曼滤波）都是 OpenCV 与机器人视觉的通用方法，不含任何来源不明的代码。

## 二、AI 的使用范围

| 环节 | 谁做的 |
|---|---|
| 需求理解与判据定稿（只做红色、四点 + 中心、PnP 位置、耗时） | 本人 |
| 参考项目调研、选型（传统视觉路线，不引入深度学习） | 本人定方向，AI 查资料并读源码 |
| 代码实现（掩膜、灯条、配对、PnP、跟踪、绘制、主程序） | **AI 生成**，本人在本机验证 |
| 参数实测（颜色纯度、灯条几何、配对约束、重投影门槛、跟踪参数） | AI 跑扫描，本人确认取舍 |
| 缺陷定位与修复（重投影门槛过紧、IPPE 镜像歧义、状态机时序） | AI 定位与修复，本人复核 |
| 文档撰写（README、需求对照、本文件） | AI 起草，本人核对 |
| 结果验收 | 本人 |

补充说明两点：

1. **没有使用深度学习**，也没有引用任何外部权重文件。考核环境中除 OpenCV 外无额外依赖。
2. 代码中的阈值不是"经验值"：每个阈值都对应一次本机实测（见 README「关键参数的依据」），可以在回归脚本里复现。

## 三、本人完成的内容

- 明确任务边界：只检测红色、输出四角点与中心、PnP 相机系位置、逐帧耗时；
- 确定技术路线：传统视觉而非 YOLO——理由是考核数据为离线视频、目标为单色高亮灯条，颜色 + 几何判据足够，且不引入训练与权重依赖；
- 确认关键取舍：检出率优先还是精度优先（最终选检出率优先，代价写明在 README 已知限制第 7 条）；
- 在本机复现全部指标：干净构建零 warning、两段视频回归、假阳性核对；
- 逐帧抽查检出结果，确认角点贴合、中心点正确；
- 核对文档与代码一致性（README 的每条参数都能在 `include/config.hpp` 找到）。
