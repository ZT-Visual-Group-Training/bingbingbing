# 视频处理解析 —— 从"处理一张图"到"处理一段视频"

> 这份文档回答一个核心疑问：**前面写的不是处理图像的代码吗？怎么用到视频上？**
> 答案一句话：**视频就是一连串连续的图像，视频处理 = 对每一帧重复你已有的图像处理流程。**

---

## 一、先建立核心认知：视频到底是什么

把视频想成**一叠快速翻动的照片（幻灯片）**：

- 每秒显示 30 张照片 → 叫 30 FPS（帧率）
- 每一张照片 → 叫一**帧**（frame），本质就是一张 `cv::Mat` 图片
- 人眼看着连续，是因为翻得快；程序眼里它就是**一堆图片排成队**

所以——

| | 图片版（main.cpp） | 视频版（main_video.cpp） |
|---|---|---|
| 输入 | `imread()` 读**一张**图 | `VideoCapture` 循环读**很多帧** |
| 处理 | `detect()` 一次 | `detect()` **每帧调一次** |
| 输出 | `imwrite()` 存一张图 | `VideoWriter` 把每帧结果写成视频 |
| 结构 | 直线跑一遍 | **外面套一个 while 循环** |

**关键结论**：检测算法（`detect()`、`drawResult()`）一个字都不用改。你之前学的灯条筛选、配对、PnP 全部原样复用。视频版新增的只是"怎么把帧读进来"和"怎么把结果写出去"这两头。

## 二、整条流水线（对照代码看）

```
打开视频 VideoCapture
        │
        ▼
 ┌───── while 循环（视频没读完就一直转）─────┐
 │  ① cap.read()        读一帧 → cv::Mat      │
 │  ② detect()          检测装甲板（你已有） │
 │  ③ drawResult()      画框/坐标/耗时（已有）│
 │  ④ writer.write()    把结果帧写进视频      │
 │  ⑤ waitKey(1)        刷新显示窗口          │
 └──────────────────────────────────────────┘
        │
        ▼
 release() 释放 → 得到处理后的视频文件
```

代码位置：`main_video.cpp` 第 141 行开始的 `while (true)` 就是这个循环。

## 三、新概念逐个拆解（这是你要新学的东西）

### 1. `cv::VideoCapture` —— 视频的"读取器"

```cpp
cv::VideoCapture cap(videoPath);   // 打开视频文件
if (!cap.isOpened()) { ... }       // 检查是否打开成功
```

- 类比：`imread` 是读一张图，`VideoCapture` 是"打开一个视频流"，之后可以一帧一帧往外取。
- 也能传摄像头编号：`cv::VideoCapture cap(0);` 就是打开电脑摄像头（考核读视频文件用不上，但答辩可以现场演示）。
- `cap.get(cv::CAP_PROP_FPS)` 读帧率，`CAP_PROP_FRAME_WIDTH/HEIGHT` 读分辨率，`CAP_PROP_FRAME_COUNT` 读总帧数。

### 2. `cap.read(frame)` —— 取一帧

```cpp
if (!cap.read(frame) || frame.empty()) break;   // 读到结尾就退出
```

- 每调用一次，就往 `frame` 里装入下一帧图像（一个普通 `cv::Mat`）。
- 返回 `true` = 取到了，`false` = 视频读完了。**这就是循环的停止条件**。
- 取出来的 `frame` 和你 `imread` 得到的图没有任何区别，直接丢给 `detect()` 即可。

### 3. `cv::VideoWriter` —— 视频的"写入器"

```cpp
cv::VideoWriter writer(outPath,
    cv::VideoWriter::fourcc('M','J','P','G'),  // 编码格式
    fps, cv::Size(width, height));             // 帧率、分辨率要和输入一致
writer.write(result);   // 每处理完一帧，写进去
writer.release();       // 结束必须释放，否则文件不完整、打不开
```

- 类比：`imwrite` 存一张图，`VideoWriter` 把一帧帧结果**拼成视频文件**。
- `fourcc` 是四个字符组成的编码格式代号。`MJPG` 兼容性最好——Windows、Ubuntu、VLC、浏览器基本都认。**先记这一种就够。**（Ubuntu 上 `XVID`、`mp4v` 也常用）
- 三个参数（编码、帧率、尺寸）必须和输入视频对上，否则输出的视频会播不了或速度不对。

### 4. `cv::waitKey(1)` —— 视频显示的关键（和图片版不同！）

```cpp
// 图片版：等用户按任意键才继续
cv::waitKey(0);

// 视频版：只等 1 毫秒就继续，画面才能连续播放
cv::waitKey(1);
if (cv::waitKey(1) == 27) break;   // 27 是 Esc 键，可提前退出
```

**这是图片版改视频版最容易踩的坑**：如果视频循环里写了 `waitKey(0)`，程序会卡在第一帧等你按键，视频就"不动"了。记住：**视频用 1（或 16~33），图片用 0**。

### 5. 帧率 FPS 和"处理耗时"的关系（考核会问）

- 输入视频 30fps → 意味着每帧必须在 **33 毫秒**内处理完，才能实时播放。
- 程序里测的"处理耗时"是这个算法跑一帧用了多久（实测约 **3~5 ms**），远小于 33ms → 所以能轻松实时。
- 输出视频的播放速度由 `VideoWriter` 写的 fps 决定（我们照抄输入的 fps），所以结果视频看上去和原视频一样快。
- 答辩时可以说："算法单帧约 5ms，远高于考核视频 30fps 的实时要求。"

### 6. `release()` —— 收尾必须做

```cpp
cap.release();
writer.release();
cv::destroyAllWindows();
```

不释放的话，输出视频文件可能**没有写完整**（缺索引），导致播放器打不开。这是新手常见问题。

## 四、怎么用到你的考核视频上（操作步骤）

### 第 1 步：把考核视频放进项目

把老师给的 `.mp4` / `.avi` 拷到 Ubuntu 项目目录，比如 `~/armor_vision/data/test.mp4`。

### 第 2 步：命令行运行

```bash
cd ~/armor_vision
cmake -S . -B build && cmake --build build     # 第一次编译（改代码后只需第二条）

# 处理考核视频（--no-show 无图形界面时用；有桌面可以去掉，边跑边看）
./build/armor_video --video data/test.mp4 --out result.avi --no-show

# 如果老师给了相机参数文件
./build/armor_video --video data/test.mp4 --camera data/camera.yaml --out result.avi

# 想单帧看看效果
./build/armor_video --video data/test.mp4 --no-show --dump-frame 100
```

### 第 3 步：提交

把 `result.avi`（处理后的视频）按考核要求交上去，README 里写清楚运行命令。

**就这么简单**——算法部分完全不用动，只要把视频路径传进去。

## 五、关于考核给的"同步 IMU 数据"

考核文档提到"与视频同步的 IMU 数据"。这里的**同步**是关键：

- 每一帧图像，都配一份**同一时刻**的 IMU 读数（加速度、角速度、姿态角）。
- 如果你要做附加项"完整自瞄系统"，可以在 `while` 循环里，**按帧号**取出对应的 IMU 数据，用来补偿机器人自身的抖动。
- 基本要求（检测 + PnP + 显示）**不需要用 IMU**，先把视频逐帧检测跑通即可。

示意（附加项才需要，框架里暂未实现）：

```cpp
int frameNo = 0;
while (cap.read(frame)) {
    ImuData imu = imuList[frameNo];   // 按帧号取同步的 IMU 数据
    // ... 用 imu 补偿相机运动 ...
    ++frameNo;
}
```

## 六、常见坑（小白最容易卡住的地方）

| 坑 | 现象 | 解决 |
|---|---|---|
| `waitKey(0)` 写进视频循环 | 卡在第一帧不动 | 改成 `waitKey(1)` |
| 输出视频打不开 | 没 `release()` 或编码不对 | 结尾 `writer.release()`，用 MJPG 编码 |
| 输出视频时长不对/播放太快 | fps 和输入不一致 | `VideoWriter` 的 fps 用 `cap.get(CAP_PROP_FPS)` |
| 读不到视频帧率（fps=0） | 有些编码格式读不出 fps | 代码里已兜底设为 30 |
| Ubuntu 报找不到编码器 | 缺 ffmpeg 库 | `sudo apt install ffmpeg libavcodec-dev`（OpenCV apt 版一般自带） |
| 忘记改相机参数 | PnP 距离明显不对 | 用 `--camera` 传老师给的内参文件 |

## 八、一句话总结

> 视频 = 一串图片帧。把你已经写好的"检测一张图"的代码，放进 `while(cap.read())` 循环里对每帧跑一遍，再把结果用 `VideoWriter` 写回视频——这就是视频处理的全部。算法没变，只多了"读帧""写视频""waitKey(1)"这几个新东西。
