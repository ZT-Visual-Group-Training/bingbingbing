# 装甲板检测完整框架 · 小白学习指南

> 配套代码就在这个文件夹里（`ArmorDetector.h` / `ArmorDetector.cpp` / `main.cpp` / `CMakeLists.txt`）。
> 这份文档按"先懂全局 → 再逐块拆 → 最后动手改"的顺序写，建议边看代码边读。

---

## 〇、这套框架是干什么的

它把考核的**基本要求 3 项**全实现了：

| 考核要求 | 本框架对应功能 |
|---|---|
| 检测红/蓝装甲板，标出 4 个角点 + 中心点 | `detectLights` + `matchLights`（画红/黄框、红角点、紫中心） |
| 用相机参数 + PnP 估计三维位置 | `solveArmorPnP`（`cv::solvePnP`） |
| 显示检测结果、三维位置、处理耗时 | `drawResult`（画面左上角 `Time: xx ms`） |

一句话串起整条流水线：

> **读图 → 颜色掩膜（红蓝各一遍）→ 找轮廓 → 椭圆拟合筛出灯条 → 相邻两根配成板 → 取四角点 → PnP 解出三维坐标 → 画框/角点/坐标/耗时**

你之前在 demo5 已经掌握的是前半段（掩膜→灯条），本框架**新增的只有后半段**：配对、四角点、PnP、显示计时。

## 二、4 个核心数据结构（先看懂"数据长什么样"）

写代码前先看清数据在流通过程中会变成什么形状，这是读懂算法的关键。

### 1. `CameraCalib` —— 相机标定参数
```cpp
double fx = 600, fy = 600;   // 焦距（像素）
double cx = 320, cy = 180;   // 主点（光心位置）
double k1,k2,p1,p2,k3;       // 畸变系数
```
它提供 `cameraMatrix()` 和 `distCoeffs()` 两个函数，把上面的数字拼成 OpenCV 要的矩阵。**默认值只匹配本程序的合成图，考核必须换成老师给的参数！**

### 2. `ArmorParam` —— 所有可调阈值
分成三组：颜色阈值（`redLowH1`…）、灯条筛选阈值（`lightAreaMin`…，**这些你 demo5 已学**）、新增的配对阈值（`pairHeightRatioMax`…）和装甲板真实尺寸（`armorWidth/armorHeight`，单位米）。

### 3. `LightBar` —— 一根灯条
```cpp
cv::RotatedRect rect;  // 拟合出的旋转矩形
cv::Point2f center;    // 中心点
float height, angle;   // 长度、倾角
ArmorColor color;      // 红 or 蓝
```

### 4. `Armor` —— 一块装甲板（最终成果）
```cpp
std::vector<cv::Point2f> corners; // 4个角点
cv::Point2f center;               // 中心点
cv::Vec3d tvec, rvec;             // 三维位置、朝向
double distance;                  // 距离
bool valid;                       // PnP 是否成功
```

**数据演变链**：`cv::Mat 图片` → `vector<LightBar> 一堆灯条` → `vector<Armor> 一堆装甲板`

## 三、`main.cpp`：程序怎么跑起来的

按顺序 5 件事：

1. **解析命令行参数**（`--image` 指定图、`--camera` 指定相机参数、`--out` 输出名、`--no-show` 不弹窗）。
2. **读图**：没给图就用内置合成图（左边红板 + 右边蓝板），所以你一运行就能看到效果。
3. **读相机参数**：给了 `--camera xxx.yaml` 就读文件，否则用占位默认值。
4. **计时 + 检测**：
   ```cpp
   auto t0 = std::chrono::steady_clock::now();   // 记开始时间
   auto armors = detector.detect(bgr, calib);    // 核心！一条函数跑完整条流水线
   auto t1 = std::chrono::steady_clock::now();   // 记结束时间
   double ms = duration<double, milli>(t1-t0).count();  // 毫秒数
   ```
5. **画结果 + 保存 + 打印**三维坐标和耗时。

## 四、`ArmorDetector.cpp`：五大步骤逐个拆（核心中的核心）

### 步骤 1 · `makeColorMask` —— 生成颜色掩膜（已学，只加了蓝色）
- 转 HSV，红色取两段（跨 0/180 边界）、蓝色取一段（`H` 在 100~130）。
- `inRange` 出黑白图 → 开运算去噪、闭运算补孔。
- 区别旧代码：多了 `ArmorColor color` 参数，红蓝共用同一套逻辑。

### 步骤 2 · `detectLights` —— 检测灯条（已学）
- 对红、蓝各跑一遍掩膜→`findContours`→面积/点数过滤→`fitEllipse`→角度/长宽比/填充率过滤。
- 通过的封装成 `LightBar`。**这整段就是你 demo5 学的那套。**

### 步骤 3 · `matchLights` —— 灯条配对（★新增，重点）

**要解决什么问题**：上一步得到一堆独立灯条，程序得判断"哪两根属于同一块板"。

**核心技巧**：按中心 x 坐标**从左到右排序**，然后只检查**相邻**两根。因为同一块板的左右灯条在画面上必然相邻。这样把"任意两两组合"的 O(n²) 降成 O(n)。

六道配对条件（全过才是一对）：
```cpp
if (L.color != R.color) continue;                     // ① 颜色一样
if ((hMax-hMin)/hMax > 0.6)   continue;               // ② 高度接近
if (fabs(L.center.y - R.center.y) > 40) continue;     // ③ 中心差不多高
if (fabs(L.angle - R.angle) > 15) continue;           // ④ 倾角接近
if (dist < 10) continue;                              // ⑤ 不重叠
if (dist / hMax > 8) continue;                        // ⑥ 离得不算太远
```
> 这些阈值都在 `ArmorParam` 里，名字以 `pair` 开头，调参时改这里。

### 步骤 4 · 取四角点（★新增，最容易出错）

配对成功后，从两根灯条各取两个角点，拼成装甲板的 4 个角：

- 左灯条：取它**左侧**的两个顶点 → 左上、左下
- 右灯条：取它**右侧**的两个顶点 → 右上、右下

`sidePoints(bar, leftSide)` 这个小工具负责：把旋转矩形的 4 个顶点按 x 排序，左灯条取 x 最小的两个、右灯条取 x 最大的两个，再按 y 分上下。

**存入顺序必须固定**（顺时针）：
```cpp
corners[0] = 左上;  corners[1] = 右上;
corners[2] = 右下;  corners[3] = 左下;
```
⚠️ **这是全项目最高频的 bug 来源**：角点顺序一旦乱了，PnP 算出的三维位置会完全错误。

中心点 = 四角坐标求平均。

### 步骤 5 · `solveArmorPnP` —— PnP 测距（★新增，考核核心）

**一句话原理**：已知装甲板真实尺寸，量出它在照片里占多少像素，用近大远小反推距离。

PnP 需要"两组一一对应的点"：

| 组别 | 是什么 | 谁提供 | 单位 |
|---|---|---|---|
| `objectPoints` | 4 个角在**真实世界**的坐标 | 你按 `armorWidth/armorHeight` 算 | **米** |
| `imagePoints` | 同样这 4 个角在**照片**里的像素坐标 | 上一步的 `corners` | 像素 |

`objectPoints` 这样造（板中心当原点，z=0 因为是平面）：
```cpp
float w = armorWidth/2, h = armorHeight/2;   // 半宽半高
{ (-w, h, 0),   // 左上 —— 对应 corners[0]
  ( w, h, 0),   // 右上 —— 对应 corners[1]
  ( w,-h, 0),   // 右下 —— 对应 corners[2]
  (-w,-h, 0) }  // 左下 —— 对应 corners[3]
```
⚠️ **每一行要和 corners 的顺序严格对应！**

调用 OpenCV：
```cpp
cv::solvePnP(objectPoints, armor.corners,
             calib.cameraMatrix(), calib.distCoeffs(),
             armor.rvec, armor.tvec, false, cv::SOLVEPNP_ITERATIVE);
armor.distance = cv::norm(armor.tvec);   // 直线距离 = tvec 向量长度
```
`tvec` 就是要的答案：装甲板中心在相机坐标系下的三维位置（x 左右、y 上下、z 前后），**单位米**。

### 步骤 6 · `drawResult` —— 显示（★新增）
- 绿框 = 红板，黄框 = 蓝板（BGR 里黄色是 `Scalar(0,255,255)`）。
- 红小圆 = 4 个角点，紫圆 = 中心点。
- 白色文字 = `X:.. Y:.. Z:.. D:..m`（三维坐标 + 距离）。
- 左上角黄色 `Time: xx ms` = 处理耗时。

## 五、跑一遍的真实数字（帮你对上号）

用内置合成图运行，终端输出是这样的：

```
[armor] 检测到装甲板: 2 块
  装甲板#0 颜色=红 中心(152,179) 三维XYZ(m)=(-0.37, -0.00, 1.29) 距离=1.34m
  装甲板#1 颜色=蓝 中心(472,179) 三维XYZ(m=( 0.34, -0.00, 1.29) 距离=1.33m
[armor] 处理耗时: 8.2 ms
```

怎么读懂这组数字：
- 检测到 **2 块**：红、蓝各一块，说明双色检测 + 配对都对了。
- `Z ≈ 1.29m`：板子离相机约 1.3 米（合成图用占位参数算出，仅演示）。
- `X`：红板 -0.37 在左边，蓝板 +0.34 在右边 —— 和你看到的位置一致，符号对了。
- `Y ≈ 0`：两板都在画面中间高度，正确。

## 六、怎么改成考核能用的版本（重点！）

框架现在能在合成图上跑通，但要用于考核，必须做 3 件事：

### 1. 换成真实相机参数
老师会给相机内参和畸变（通常是 `.yaml` 或 `.xml`）。做成这样的 YAML：
```yaml
%YAML:1.0
image_width: 640
image_height: 360
camera_matrix:
   rows: 3
   cols: 3
   data: [ 600., 0., 320., 0., 600., 180., 0., 0., 1. ]
distortion_coefficients:
   rows: 5
   cols: 1
   data: [ 0., 0., 0., 0., 0. ]
```
运行时加参数：`./程序 --camera 你的参数.yaml --image 考核视频帧.png`

### 2. 换成真实装甲板尺寸
改 `ArmorParam` 里的 `armorWidth` / `armorHeight`（单位**米**）。比如老师说是 425mm×245mm，就填 `0.425f` / `0.245f`。⚠️ 单位写错（填成 425）会让距离差 1000 倍。

### 3. 改成读视频
`main.cpp` 现在是读单张图。考核给的是视频，把读图那段换成 `cv::VideoCapture`：
```cpp
cv::VideoCapture cap("考核视频.mp4");
cv::Mat frame;
while (cap.read(frame)) {          // 一帧一帧读
    auto t0 = steady_clock::now();
    auto armors = detector.detect(frame, calib);
    auto t1 = steady_clock::now();
    cv::Mat out = ArmorDetector::drawResult(frame, armors, ms(t1-t0));
    cv::imshow("result", out);
    if (cv::waitKey(1) == 27) break;   // 按 ESC 退出
}
```

## 八、常见坑（踩过的人都会遇到）

| 现象 | 原因 | 怎么修 |
|---|---|---|
| 三维坐标明显错乱 / 距离离谱 | 角点顺序和 `objectPoints` 没对应上 | 检查 corners 的 0/1/2/3 顺序 |
| 距离差约 1000 倍 | `armorWidth/armorHeight` 用了毫米 | 换成米（除以 1000） |
| 检测不到装甲板 | 颜色阈值或灯条筛选太严 | 调 `minS/minV`、`lightAreaMin`、`aspectRatioMax` |
| 两灯条配不上对 | 配对阈值太严 | 放宽 `pairHeightRatioMax`、`pairYDiffMax` |
| Windows 运行时报缺 DLL | debug 版 OpenCV 库不全 | 用 Release 配置编译（本框架已验证） |
| Ubuntu 编译找不到 OpenCV | 没装 `libopencv-dev` | `sudo apt install libopencv-dev` |

## 九、验证方法（别只看"没报错"）

1. **看可视化**：四角点是否准确落在装甲板四角（不是灯条四角）。
2. **看符号**：板在左边 X 应为负、右边为正；正面朝向时 Z 为正。
3. **重投影检查**（进阶）：把解出的 3D 点用 `projectPoints` 投回图像，和观测角点比较，误差应只有几个像素。
4. **已知距离验证**：拿一张已知距离的图，看 Z 是否接近真实值。
