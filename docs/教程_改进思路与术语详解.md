# 改进思路与术语详解

给答辩准备的：这一版是怎么一步步变成现在这样的、踩过哪些坑、术语怎么解释、可能被问什么。

所有数字都来自本机两段考核视频（视频1：1770 帧、1440×1080、装甲板持续转动；视频2：1240 帧、一直正对）。

## 一、五轮改进历程

| 阶段 | 改了什么 | 检出率 | 闪烁 | 为什么改 |
|---|---|---|---|---|
| v1 初版 | 颜色掩膜 + minAreaRect + 四约束配对 + IPPE PnP + 三重门槛（重投影 2 px） | 67.06 % | 18 | 跑通全流程 |
| v2 | 重投影门槛 2 → 4 px | 84.92 % | 30 | 发现真板在斜视时重投影本来就有 3~6 px |
| v3 | 门槛 → 6 px；选候选时用上一帧位置做先验；卡尔曼新息检验 | 92.49 % | 11 | 门槛放宽后错配解变多，需要两道闸 |
| v4 | 板尺寸改考核文档 135×56；状态机修复（离群并入漏检、先验只在测量被接受时更新） | 90.06 % | 4 | 修评审指出的时序缺陷 |
| v5 | 灯条碎片拼接、单端外推、右下反光修剪、板面明暗对比度 | 90.06 % | 4 | 处理遮挡与粘连 |

**关键认知**：瓶颈不在颜色阈值。把通道差阈值从 40 降到 8，掩膜像素从 9632 涨到 97700，检出帧数**一帧没多**——真板一直在掩膜里，是几何校验把它们毙了。

## 二、九个实现缺陷案例

| # | 现象 | 根因 | 怎么发现的 |
|---|---|---|---|
| 1 | 通道差掩膜恒为 0 像素，颜色分割退化成纯 HSV | `cv::max(ch[1], ch[2])` 把 G 和 **R** 取了 max，让 R 减它永远 ≤ 0；正确是 `max(G, B)` | 打印 `countNonZero` 三个掩膜的像素数，diff=0 一眼现形 |
| 2 | PnP 全部被 yaw 检查毙掉 | 物体坐标系用 y 向上，正视时旋转矩阵第三列是 (0,0,−1)，yaw 算出 180° | 打印 IPPE 两个解的 `reproj / nz` 并与图像核对 |
| 3 | 距离系统性偏大 | 角点取灯条**中心线**，3D 模型却按整板尺寸，像素四边形与模型尺度不一致 | 拿像素宽高比 2.58 去比 127/50=2.54 与 135/56=2.41，只有前者吻合 |
| 4 | yaw/pitch 逐帧来回跳（实测 +11.5° 跳到 −18.1°） | 4 点解平面位姿，IPPE 给两个几乎等价的解，单纯取"重投影最小"会在两支路间翻转 | 连续帧 trace 出 pitch 序列，肉眼可见方波 |
| 5 | 连续 20 帧被新息检验拒绝，框还照样画 | 离群分支只做 `++lostFrames_` 就 return，绕过了状态转换和 15 帧超时 | 外部评审逐行核对指出 |
| 6 | 被拒绝的错配解影响下一帧选候选 | 主循环先更新 `lastXyz`，再交给跟踪器判决，顺序反了 | 同上 |
| 7 | 一支 IPPE 解超限，另一支全过也被连坐丢弃 | 先按连续性选支，再对这一支查门槛 | 同上 |
| 8 | 倾角 20° 的平行约束形同虚设 | `tiltDeg` 取了绝对值，左倾 20° 和右倾 20° 差值算成 0 | 同上 |
| 9 | 灯条被数字光晕粘宽（15 px → 40 px），外缘角点偏 12 px | 掩膜里灯条中心过曝成白色抓不到，只剩红边（空心 C 形），旁边亮斑一粘就把 minAreaRect 撑大 | 导出掩膜裁图放大看 |

## 三、术语详解

### 图像与颜色

| 术语 | 一句话解释 |
|---|---|
| 掩膜（mask） | 和原图一样大的黑白图，白的地方表示"这块像素符合条件" |
| HSV | 用色相/饱和度/亮度描述颜色。比 BGR 更适合做颜色分割，因为亮度变化不影响色相 |
| 色相 H | 颜色种类。OpenCV 里范围是 0~180，红色跨 0 边界，所以拆成 [0,12] 和 [165,180] 两段 |
| 饱和度 S | 颜色纯不纯。灯条中心过曝后 S 掉到很低，所以纯 HSV 会漏掉灯芯 |
| 亮度 V | 三个通道里最大的那个值 |
| 通道差 | 直接算 `R − max(G,B)`。红灯的 R 明显比另外两个高，这招对过曝最鲁棒 |
| 形态学开运算 | 先腐蚀后膨胀 → 去掉孤立小噪点 |
| 形态学闭运算 | 先膨胀后腐蚀 → 把断开的细段接起来。核取 3×9（竖长）是因为灯条是竖的 |
| 闭运算核 | 结构元素大小。纵向给大一点不会把左右两根灯条糊到一起，横向就会 |
| 连通域 | 掩膜里连成一片的像素块 |
| 轮廓 | 连通域的外边界点集，`findContours` 得到 |
| 等值线（轮廓点） | 轮廓上的每一个像素坐标 |

### 几何量

| 术语 | 一句话解释 |
|---|---|
| 最小外接矩形（RotatedRect） | 能框住一个轮廓的最小**可旋转**矩形，给中心、宽高、角度 |
| 长宽比 | 长边 / 短边。灯条约 3.3~4.5，方块接近 1，用来区分 |
| 质心 / 重心 | 轮廓点的平均位置 |
| 像素当量 | 1 个像素对应多少毫米。1.7 m 处约 0.73 mm/px |
| 透视投影 | 三维点按 `u = fx·X/Z + cx` 落到图像上。近大远小就是这个 |
| 齐次坐标 | 把平移写成矩阵乘法的技巧，PnP 内部用 |

### 相机与位姿

| 术语 | 一句话解释 |
|---|---|
| 内参 | 相机自己的属性：焦距 fx/fy、主点 cx/cy、畸变系数 |
| 畸变系数 | 镜头把直线拍弯的程度，k1/k2/p1/p2/k3 |
| 标定 | 用已知尺寸的棋盘格反推内参。本项目用 40 张，重投影 RMS 0.19 px |
| 相机坐标系 | 原点在光心，x 向右、y 向下、z 向前（沿光轴） |
| 刚体变换 | 只有旋转 + 平移，不改变物体形状 |
| 旋转向量（rvec） | 用一个三维向量表示旋转，方向是转轴，长度是转角 |
| 旋转矩阵（R） | 3×3 正交矩阵，`Rodrigues` 可以在它和旋转向量之间转换 |
| 平移向量（tvec） | 物体原点在相机系下的坐标 |
| yaw / pitch / roll | 偏航（左右转）/ 俯仰（上下抬）/ 翻滚（绕视线转）。本项目的 yaw、pitch 取自板面法向 |
| 板面法向 | 板子朝向。旋转矩阵的第三列就是它在相机系下的方向 |
| PnP | Perspective-n-Point：已知 n 个三维点和它们的像素位置 + 内参，求位姿 |
| IPPE | 一种 PnP 解析解法，专门用于**共面**点，比迭代法快且稳 |
| 重投影误差 | 把解出来的位姿反算回图像，看预测点与实测点差几像素。**它是"这个解到底存不存在"的证据** |
| 镜像歧义 | 4 个共面点无法区分"正对"和"镜像翻转"两种姿态，两个解的重投影几乎一样 |

### 跟踪与滤波

| 术语 | 一句话解释 |
|---|---|
| 卡尔曼滤波 | 用"预测 + 测量加权"估计状态。预测准就更信预测，测量准就更信测量 |
| 状态量 | 被估计的东西。本项目是 `[x, y, z, vx, vy, vz]` 六维 |
| 协方差矩阵 | 表示"我对自己估计有多不确定" |
| 过程噪声 Q | 模型本身的不准程度。目标会加速，所以速度项给大一点 |
| 测量噪声 R | 测量值有多抖。本项目按实测跳变 σ≈50 mm 标定 |
| 新息 | 测量值 − 预测值 |
| 马氏距离 | 把新息按协方差归一化后的距离。单位是"几个标准差"，不是毫米 |
| 卡方分布 | 马氏距离平方在理想情况下服从的分布。3 自由度 0.999 分位是 16.27 |
| 发散 | 滤波器越跑越偏，预测跑出合理范围 |
| 状态机 | 用有限个状态描述跟踪进程：`lost → detecting → tracking → temp_lost → lost` |
| 确认帧数 | 连续检出多少帧才认为真的锁定了（本项目 5 帧） |
| 保持帧数 | 丢失后还能靠外推撑多少帧（本项目 15 帧） |

### 工程指标

| 术语 | 一句话解释 |
|---|---|
| 检出率 | 几何门通过帧 / 总帧 |
| 有效位姿率 | 跟踪器接受的测量帧 / 总帧。比检出率严格，因为错配解会被拒 |
| 框显示率 | 有框的帧 / 总帧，含预测框，所以最高 |
| 闪烁 | 框从有到无的次数，越少越稳 |
| FPS | 每秒处理帧数 = 1000 / 单帧毫秒 |
| 时延 | 从拍照到输出结果的延迟，不等于 1/FPS |

## 四、20 题答辩问答

**1. 为什么不用 YOLO？**
考核数据是离线视频、目标为单色高亮灯条，颜色 + 几何判据已经能把检出做到 90 %；用网络要引权重、要训练、要额外依赖，而且考核环境只保证 OpenCV。同理也要说明代价：粘连、遮挡时传统方法更脆。

**2. 怎么保证检出来的不是误检？**
三重几何裁决，最后一道是重投影误差——它检验的是"这 4 个像素点能不能被一块 135×56 的刚性板一次解释"。错配的亮条对能凑成框，但没有任何位姿能同时满足那 8 个方程。实测真板中位 1.18 px，窗外灯管凑的假板 5~30 px。

**3. 重投影误差具体怎么算？**
把解出的 R、t 代回去，用 `projectPoints` 把模型 4 个角点重新投到图像上，和检测到的 4 个像素点逐个量距离取平均。

**4. 门槛为什么从 2 px 放到 6 px？**
板子转到侧面时一根灯条被挡住一截或被光晕粘宽，真板自身就有 3~6 px 不自洽。卡 2 px 时检出率只有 67.06 %；6 px 时 92.49 %，8 px 只多 0.9 个百分点、收益饱和。

**5. 旋转的时候为什么容易跟丢？**
两个原因：① 板面侧过去时只剩一根灯条，四点凑不齐；② 一根灯条被遮挡后长度变短，四点不再刚体自洽。前者靠跟踪器保持 15 帧，后者靠放宽门槛 + 时序检验。

**6. 卡尔曼为什么用 6 维状态？**
位置 3 维 + 速度 3 维。只有位置的话，丢帧时没法外推（不知道往哪走）；加速度不进状态是因为 90 ms 的外推窗口内匀速假设够用。

**7. 为什么用马氏距离而不用欧氏距离？**
欧氏距离是"差了多少毫米"，马氏距离是"差了几个标准差"。协方差大的方向（刚起步、速度还没估准）宽容，协方差小的方向严格，这是欧氏距离做不到的。

**8. 新息门限 40 是怎么定的？**
按实测位置噪声 σ≈50 mm 反推。理论值（卡方 0.999）是 16.27，但实测会把一半真实测量也拦掉，所以放到 40；代价是极个别大跳变要漏过去。

**9. IPPE 为什么有两个解？怎么选？**
4 个共面点的位姿存在镜像对称性，两个解的重投影几乎一样。本项目先用 `nz > 0`（板面朝向相机）过滤，再按"与上一帧姿态最接近"或"|pitch| 最小"择一。

**10. yaw/pitch 读数为什么不能全信？**
存在上面说的镜像歧义，姿态角可能差十几度。位置（xyz）不受影响——两个解算出来的距离差小于 0.1 %。

**11. 测距误差有多大？**
主要来源是板尺寸标称值。按考核文档取 135×56 mm；若实际灯条可见发光区比标称短，会有数个百分点的系统偏差。同一段视频内的相对变化不受影响。

**12. 135×56 这个尺寸哪来的？**
考核文档原文「小装甲板尺寸为宽 135 mm、高 56 mm，高度取灯条长度」。我们一开始用自己测的 127×50，改成文档值后检出率只掉 0.3 个百分点（92.71 → 92.43），所以采用文档值。

**13. 角点为什么要取灯条外缘而不是中心？**
3D 模型按整板尺寸建模，角点必须落在板的外缘才对得上。取灯条中心线的话像素四边形比模型小一圈，距离会系统性偏大。

**14. 掩膜里灯条为什么是空心的？**
灯条中心过曝成白色，白色没有色相、`R−max(G,B)` 也接近 0，颜色判据抓不到；剩下的红边就成了一圈空心轮廓。

**15. 单帧模式和视频模式为什么结果不一样？**
视频模式有跟踪器：连续 5 帧才确认、丢失 15 帧才丢目标、离群测量会被拒绝。单帧模式没有历史，一条命令只解一帧。

**16. 耗时怎么测的？为什么波动这么大？**
`cv::getTickCount` 包住「检测 + 选板 + 跟踪」，不含绘制。虚拟机里 CPU 抢占严重，同一份代码测过 10~70 ms/帧，所以要跑多次取中位。

**17. 窗外的暖白光带怎么排除的？**
靠红纯度：真灯条 `R−G` 实测 64~73，暖白光带只有 43。阈值取 55。

**18. 蓝色怎么扩展？**
把 `buildRedMask` 里的 H 段和通道差 `R−max(G,B)` 换成 `B−max(R,G)`，下游的灯条筛选、配对、PnP、跟踪全部复用。

**19. 剩下 10 % 没检出的是什么？**
主要是板子转到接近侧向时只剩一根灯条可见的帧，以及灯条被完全遮挡的帧。这些帧物理上没有四个角点可解。

**20. 现场光照变了怎么办？**
颜色阈值需要重标。做法是跑一遍新视频，把每根候选灯条的 `R−G`、`R−B` 打印出来（`--debug` + trace），取真灯条的下界和干扰源的上界的中点当阈值。不要直接调总阈值——先看是哪个判据在拦。
